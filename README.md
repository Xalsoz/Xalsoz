# gd-difficulty

Оценка сложности демонов Geometry Dash по таймингам. Есть две части:

- **Мод для игры** (`probe/`): сам проходит уровень (или берёт готовый макрос) и для
  каждого клика измеряет окно допуска: сдвигает клик раньше и позже, пока
  игрок не умрёт. Управляется окном в меню паузы, там же итог.
- **Программа анализа** (`gddiff/`): по окнам считает сложность кликов, секций
  и уровня, учится по демонлисту и показывает сложность для игрока на
  60, 144, 240 Гц.

## Установка

```bash
pip install -e ".[dev]"
python -m pytest -q          # тесты Python (31), включая стык с ядром мода на C++
sh probe/tests/run_tests.sh  # тесты ядра мода на игрушечной физике
```

Python 3.10+, numpy, scipy, pandas. Для тестов ядра нужен компилятор C++20.

## Основной путь: окна, измеренные в игре

1. **Подготовь макрос.** Нужен макрос xdBot, MH Replay или другого бота формата GDR (`.gdr.json` или `.gdr2`), который проходит уровень.
   ```bash
   python -m gddiff probe-prepare --macro my_level.gdr.json --out probe_input.txt
   ```
2. **Собери и поставь мод** (см. `probe/README.md`). Положи `probe_input.txt` в
   папку сохранений мода, включи в настройках мода «Probe on level start»
   и открой уровень. Мод перейдёт в режим практики и начнёт замер; твои клики
   в это время игнорируются.
3. **Забери результат** `probe_<levelID>.csv` из той же папки и разбери его:
   ```bash
   python -m gddiff windows --probe probe_12345.csv --hz 60 144 240 inf --sigma 10
   ```
   Выведет самые узкие клики, шанс пройти каждый при разной частоте кадров и
   вклад секций в сложность.
4. **Для обучения** положи файлы в набор как `windows/<level_id>.csv` и используй
   `--window measured`:
   ```bash
   python -m gddiff cv --data data/real --window measured
   python -m gddiff train --data data/real --window measured --out model.json
   python -m gddiff explain --model model.json --probe probe_12345.csv --layout level.gmd
   ```

## Набор данных на диске

```
data/real/
  levels.csv                 level_id,name,position   (1 = самый сложный)
  windows/<level_id>.csv     окна от мода (основной вариант)
  macros/<level_id>/*.json   макросы GDR JSON, если окон от мода нет
  layouts/<level_id>.gmd     или .txt со строкой уровня (режимы, скорость, видимость)
  deaths/<level_id>.csv      percent,deaths; строка percent=100 = прохождения (необязательно)
```

Позиции из списков:

```bash
python -m gddiff fetch-list --source pointercrate --out pointercrate.csv
python -m gddiff fetch-list --source aredl --out aredl.csv     # адрес API не проверен, при ошибке --url
python -m gddiff agreement --a pointercrate.csv --b aredl.csv   # потолок качества: согласие списков
```

## Способы оценки окна

| `--window` | Откуда окно | Когда |
| --- | --- | --- |
| `measured` | замер модом в игре | основной способ |
| `spread` | размах одного клика по нескольким макросам | если мода нет; от 3 макросов |
| `interval` | время до соседнего клика | один макрос; слабая оценка |

`--smooth k` берёт медиану окна по k соседним кликам (по умолчанию 5, для `measured` 1).

## Проверка на синтетике (300 уровней, 5 фолдов)

```bash
python -m gddiff synth --out data/synth --levels 300
python -m gddiff cv --data data/synth --window measured
```

| Вариант | Спирмен с позицией в списке |
| --- | --- |
| истинные окна (потолок) | 0,984 |
| **окна от мода** | **0,981** |
| 3 макроса (`spread`) | 0,934 |
| клики в секунду, без модели | 0,836 |
| 1 макрос (`interval`) | 0,789 |

Синтетический набор сам эмулирует вывод мода с теми же пределами поиска,
что в ядре на C++. Реальный мод в игре ещё не запускался.

## Сложность по частоте кадров

Игра принимает нажатие на границе следующего кадра. Игрок привыкает к средней
задержке и целится на полкадра раньше середины окна с разбросом `sigma`.
Если окно уже кадра, бывают попытки, где в окно не попадает ни одна граница
кадра: такой клик пройти нельзя при любой точности. Сложность уровня равна
сумме −log P по кликам, то есть логарифму числа попыток на прохождение без
смертей, если клики независимы. Абсолютные числа зависят от `sigma`; для
сравнения уровней и частот они полезнее, чем сами по себе.

`inf` означает ввод между кадрами (мод Click Between Frames; судя по привязкам,
в 2.208 у игры появилась отметка времени нажатия).

## Модель ранжирования

```
log d_i = log(w0 / w_i) + θ·c_i
D_s     = (Σ d_i^p)^(1/p)          p = 1: сумма, p → ∞: максимум
D       = (Σ D_s^q)^(1/q)
P(a сложнее b) = σ(β (log D_a − log D_b))
```

c_i: режим, скорость, плотность кликов, позиция в уровне, нажатие или отпускание.
Показатель при окне зафиксирован (k = 1), потому что по порядку уровней
определимы только k·p, k·q и θ/k; подробности в `gddiff/models/baseline.py`.

## Структура

```
gddiff/
  io/          макросы, строка уровня и .gmd, списки, набор на диске, файлы мода
  features/    окна допуска, признаки таймингов и видимости, сложность по частоте кадров
  models/      базовая модель, наивные оценки
  eval/        метрики, кросс-валидация, проверка видимости по остаткам
  synth.py     синтетический набор с известной истиной
probe/
  src/core/    ядро измерителя на C++ без зависимостей от игры
  src/main.cpp адаптер к GD через Geode
  tests/       игрушечная физика и тесты ядра
```

## Ограничения

- Мод проверен на типы против заголовков Geode 5.11.2 для GD 2.2081, но в игре не запускался.
- Окно меряется при остальных кликах как в макросе: это окно для данного маршрута.
- Смерть позже горизонта (по умолчанию 1 с) не ловится, и окно выходит шире настоящего.
- Платформер не поддерживается. Бинарный `.gdr2` читается, но расширения ботов (позиции, скорости) пропускаются; в JSON и `.gdr2` берутся только клики.
- Режим и скорость берутся из порталов; триггеры скорости и телепорты не учитываются.
