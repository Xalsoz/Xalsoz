# gddiff Window Probe: мод для замера окон

Мод для Geode, который измеряет окно допуска каждого клика прямо в игре. Маршрут
берётся из макроса (основной путь, работает для любого режима игры) или находится самим
модом (экспериментально, для простых уровней).

## Быстрый старт (окно в игре)

1. Положи `.geode` в `geode\mods`, запусти игру, открой уровень.
2. Нажми паузу, затем кнопку **gddiff** в правой колонке.
3. В окне:
   - **Solve + measure**: мод сам проходит уровень в режиме практики, потом мерит
     окно каждого клика найденного маршрута, считает сложность для 60, 144, 240 Гц
     и показывает самые узкие клики;
   - **Measure macro**: то же, но маршрут берётся из выбранного макроса. Кнопки `<` и `>`
     листают файлы из папки `macros` (кнопка «Open macros folder» открывает её). Читаются
     `.gdr2`, `.gdr` (GDR1, MessagePack), `.gdr.json`/`.json`, `.xd` (xdBot) и текстовый формат; Python не нужен. Макросы из папки xdBot (`geode/mods/zilko.xdbot/macros`) подхватываются сами, если она есть;
   - **Stop**: остановить и сохранить найденное.
4. Файлы пишутся в папку сохранений мода: `solved_<id>.txt` и `solved_<id>.gdr.json`
   (найденный маршрут), `probe_<id>.csv` (окна).

## Как мод проходит уровень сам

Ничего не нажимая, он смотрит, где игрок умрёт. Если до смерти далеко, идёт дальше.
Когда препятствие близко, по очереди пробует нажать (или отпустить) через 1, 2, 3...
тиков, откатываясь к чекпоинту после каждой пробы, и запоминает тик смерти. Клики,
после которых игрок доживает дольше всего, образуют окно; мод жмёт в его середине.
Если впереди тупик, он откатывается к прошлому решению и берёт следующий вариант.
Это перебор с возвратом: на коротких и средних участках работает, на длинных плотных
уровнях может застрять или идти очень долго. Если застрял, сохраняется пройденная
часть (`partial_<id>.txt`).

Окно меряется для найденного маршрута, а не для человеческого, поэтому числа могут
отличаться от замера по макросу игрока. Для сравнения уровней друг с другом это
последовательно: везде ищется самый «прощающий» путь.

## Как он мерит

1. Проигрывает макрос в режиме практики. Перед очередным кликом ставит чекпоинт.
2. Сдвигает этот клик раньше на 1, 2, 4, 8… тиков до первой смерти, затем делит
   отрезок пополам. То же самое делает в сторону «позже». Остальные клики
   остаются как в макросе.
3. Каждая проба начинается с чекпоинта. Игрок должен прожить `horizon` тиков
   после клика, иначе проба считается смертельной.
4. Результат: на сколько тиков раньше и позже ещё можно нажать (`early`, `late`).

В среднем выходит около 17 проб и 4000 тиков игры на клик. Уровень на 1500
кликов при скорости 1 займёт примерно 7 часов, поэтому есть настройка `speed`.

## Защита от неточных чекпоинтов

Стандартные чекпоинты GD восстанавливают игрока не полностью (поэтому у xdBot
свои «practice fixes»). Здесь три защиты:

- чекпоинт ставится только там, где кнопка отпущена;
- после загрузки сверяются позиция, поворот и вертикальная скорость игрока; при
  расхождении они восстанавливаются (`repair-restore`);
- после каждого нового чекпоинта исходный клик проигрывается ещё раз из чекпоинта;
  если игрок умирает, замер останавливается с советом включить `exact-restart`.

`exact-restart` начинает каждую пробу с начала уровня. Это точно, но очень
долго, поэтому включай его вместе с `stride` или диапазоном кликов. Так можно
выборочно проверить результаты замера с чекпоинтами.

## Сборка

**Проще всего через GitHub, без установки компиляторов.** Загрузи весь проект в
свой репозиторий на GitHub (вместе с папкой `.github`). Сборку запускает файл
`.github/workflows/build-mod.yml`: открой вкладку Actions, выбери «Build probe
mod» и нажми «Run workflow». Через несколько минут в разделе Artifacts
последнего запуска появится архив с файлом `gddiff.window-probe.geode`.

**Локально на Windows:** нужны Visual Studio 2022 с компонентом «Разработка
классических приложений на C++», CMake и Geode CLI (`winget install
GeodeSDK.GeodeCLI` или `scoop install geode-sdk-cli`). Затем:

```bash
geode sdk install
cd probe
geode build
```

Установка: положи `gddiff.window-probe.geode` в папку `geode/mods` рядом с
`GeometryDash.exe` и перезапусти игру.

Если у тебя другая версия, поправь `geode` и `gd.win` в `mod.json`. Под GD
2.2074 и ниже мод тоже собирается: сигнатура `processCommands` выбирается по
версии.

## Использование

1. `python -m gddiff probe-prepare --macro my.gdr2 --out probe_input.txt`
2. Положи `probe_input.txt` в папку сохранений мода. На Windows это
   `%LOCALAPPDATA%\GeometryDash\geode\mods\gddiff.window-probe` (папку можно
   создать вручную, если мод ещё ничего туда не писал).
3. Включи настройку **Probe on level start** и открой уровень.
4. В конце мод покажет окно с итогом и запишет `probe_<levelID>.csv`.

Если замер остановился, всё намеренное до этого сохраняется (`complete=0` в первой строке).

## Настройки

| Настройка | По умолчанию | Смысл |
| --- | --- | --- |
| max-shift | 48 | предел сдвига, тиков (200 мс) |
| horizon | 240 | сколько тиков прожить после клика |
| stride, first-index, last-index | 1, 0, -1 | какие клики мерить |
| speed | 1 | скорость игры во время замера |
| exact-restart | выкл | пробы с начала уровня вместо чекпоинта |
| checkpoint-on-release | вкл | чекпоинты только на отпущенной кнопке |
| repair-restore | вкл | чинить состояние игрока после загрузки чекпоинта |
| verify-restore | вкл | перепроверять исходный клик после нового чекпоинта |
| frame-source | level-time | как считать тик: как xdBot или по `m_currentProgress` |
| frame-offset | 0 | сдвиг счётчика тиков, если первый клик не совпадает |

## Что проверено, а что нет

- Ядро автопрохождения (`solve_core`) проверено на игрушечном мире с ловушками: находит
  маршрут, откатывается из тупиков, ширина найденных окон совпадает с настоящей (`tests/test_solve.cpp`).
- Ядро замера (`probe_core`) собрано и проверено на игрушечной физике: на 20 случайных
  уровнях окна найдены точно, проверены пределы соседей, поздняя смерть, неточные
  чекпоинты и потеря зажатой кнопки (`tests/run_tests.sh`).
- `src/main.cpp` проходит проверку типов против заголовков Geode 5.11.2,
  сгенерированных из привязок GD 2.2081. Запуска в игре
  не было: первый запуск лучше сделать на коротком уровне (для замера макроса с `last-index` около 20).
- Вероятные места для настройки при первом запуске: `frame-source` и
  `frame-offset` (если исходный макрос сразу умирает), а также `speed`, если
  игра ограничивает число шагов физики за кадр.

## Требования к макросу

- Макрос должен проходить уровень **без «frame fixes»** (в xdBot точность
  Vanilla или Input Fixes): мод проигрывает только клики, без исправлений
  позиции. Иначе замер остановится на первом месте, где макрос без них умирает.
- Только кнопка прыжка, не платформер.
- Во время замера мод не даёт игре ставить свои чекпоинты (автоматические или
  от объектов уровня). Если появляется «Could not place a practice checkpoint»,
  пришли лог Geode: значит, игра ставит чекпоинты не так, как ожидалось.

## Проверка воспроизведения макроса

Если замер останавливается с «The original macro dies at tick N», включи настройку «Replay test instead of measuring» и нажми «Measure macro»: мод один раз проиграет макрос и запишет позицию игрока на каждом тике в `trace_<id>.csv`. Сравнение этого файла с позициями из макроса xdBot показывает, где и почему воспроизведение расходится с записью.
